# Radar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter une page Radar qui suit des films et des saisons, vérifie C411 au lancement ou à la demande, et notifie les sorties avec alerte complète ou mi-alerte.

**Architecture:** Toute la décision (comparaison de versions, nouveautés, états, filtres) vit dans des fonctions pures sous `src/lib/radar/`, testées sans réseau. Un store module (`radarStore.ts`, lu avec `useSyncExternalStore`) porte l'état partagé entre App, menu, page et fiche Découvrir. Un moteur (`check.ts`) reçoit ses dépendances réseau en paramètre et produit des mises à jour fusionnées dans le store.

**Tech Stack:** React 19, TypeScript, TanStack Query (`queryClient.fetchQuery`), `@tauri-apps/plugin-store`, `sonner`, `motion/react`, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-radar-design.md`

## Global Constraints

- Tout texte affiché est en français correctement accentué, identifiants en ASCII. `src/lib/accents.test.ts` doit rester vert.
- Pas de tiret cadratin ni de guillemets typographiques.
- Un composant par fichier, logique pure dans des modules voisins.
- Stockage local via `LazyStore("radar.json", { defaults: {}, autoSave: false })`, jamais dans le trousseau.
- Le lancement n'attend jamais Radar.
- Aucun téléchargement automatique, aucune vérification app fermée, aucune notification macOS, uniquement C411.
- Done : `bunx tsc --noEmit`, `bun run lint`, `bun run test` passent, et l'UI est vérifiée dans l'aperçu navigateur (`bun run dev`, voir CLAUDE.md).
- `main` diverge de la branche Potager : les ancres de ce plan sont des noms de composants et de fonctions, pas des numéros de ligne.

## Review Focus

1. C411 injoignable à l'ajout d'une saison déjà commencée : le premier passage réussi plus tard reste silencieux (test Task 2 et Task 5).
2. Ligne supprimée ou modifiée pendant une vérification : le résultat en vol est ignoré pour cette ligne (test Task 4).
3. Titre proche, "Dark" suivi alors que C411 a "Dark Matter S01E01" : aucune alerte (test Task 5).
4. Relancer l'app plusieurs fois avec les mêmes releases : aucune nouvelle notification (test Task 2).
5. Pack de saison alors que TMDB ne liste encore aucun épisode : le pack ne couvre rien et la saison n'est pas terminée (test Task 2).

export type ExpectedLanguage = "vf" | "vostfr" | "any";
export type ExpectedResolution = "any" | "720p" | "1080p" | "2160p";
export interface RadarExpectation {
  language: ExpectedLanguage;
  resolution: ExpectedResolution;
  mode: RadarMode;
}
export type LanguageGroup = "vf" | "vostfr" | "vo" | "unknown";
export interface KnownVersion {
  language: LanguageGroup;
  resolution: string | null;
}
export type ContentKey = string; // "movie" ou "e6"
export type KnownVersions = Record<ContentKey, KnownVersion[]>;
export interface RadarAlert {
  content: ContentKey;
  level: "full" | "partial";
  version: KnownVersion;
  detectedAt: number;
}
export interface RadarEntry {
  id: string; // `${mediaType}-${tmdbId}-${season ?? "x"}`
  item: TmdbItem;
  season: number | null;
  expectation: RadarExpectation;
  known: KnownVersions | null; // null : point de départ pas encore établi
  baseline: ContentKey[];
  alerts: RadarAlert[];
  episodes: number[]; // numéros TMDB de la saison
  aired: number[]; // numéros déjà diffusés
  addedAt: number;
}
export type RadarRelease = Pick<ReleaseTags, "languages" | "resolution" | "scope">;

### Task 2: Calcul des nouveautés

**Files:**

**Interfaces:**

- Consumes: Task 1.
- Produces:

  - `hasExpected(entry: RadarEntry, content: ContentKey): boolean`
  - `isComplete(entry: RadarEntry): boolean`

Règles de `evaluateReleases`, par contenu :

- `entry.known === null` : point de départ. `known` est rempli, `baseline` reçoit les contenus observés, aucune alerte.
- Attendue absente avant et présente maintenant, contenu pas dans `owned` : alerte `full`, et les alertes `partial` non vues de ce contenu sont retirées.
- Mode `soft`, attendue toujours absente : une alerte `partial` par version jamais vue, si le contenu n'est pas dans `owned`.
- Mode `strict` : jamais d'alerte `partial`, mais `known` est tenu à jour.
- `alerts` = alertes existantes (moins celles remplacées) + `newAlerts`.

- Produces:

  - `type RadarStatus = "released" | "partial" | "waiting" | "finished"`, `entryStatus(entry: RadarEntry): RadarStatus`
  - `interface RadarFilters { query: string; type: "all" | MediaType; state: "all" | RadarStatus | "in-library"; mode: "all" | RadarMode }`

Correspondance bibliothèque : `LibraryEntry.tmdb` égal à l'identifiant du titre donne `certain`. Sans `tmdb`, le nom normalisé contenant le titre normalisé (et l'année pour un film) donne `uncertain`. Une entrée non enrichie (`files` vides) se lit avec `parseReleaseScope(releaseName ?? title)`, via `releaseContents`.

`entryStatus` : alerte `full` non vue donne `released`, sinon alerte `partial` donne `partial`, sinon série complète donne `finished`, film complet donne `released`, sinon `waiting`. `splitBlocks` place `released`, `partial` puis `finished` dans le premier bloc, chacun trié par titre avec `localeCompare("fr")`.

### Task 5: Moteur de vérification et notification

**Files:**

- Create: `src/lib/radar/releases.ts`, `src/lib/radar/check.ts`, `src/lib/radar/runRadarCheck.ts`, `src/lib/radar/notify.ts`

**Interfaces:**

- Consumes: Tasks 1 à 4, `tvSeason`, `TmdbEpisode`, `loadLibrary`, `getApiKey`.
- Produces:
  - `searchC411(item, c411Key, sortBy: "seeders" | "publishedAt" = "seeders")`
  - `isExactSeriesRelease(name: string, nTitles: string[]): boolean`
  - `fetchRadarReleases(entry: RadarEntry, c411Key: string): Promise<Occupant[]>` : fusionne les recherches `seeders` et `publishedAt` par `infoHash`, pour ne pas rater un épisode récent avec peu de sources. Une recherche rejetée fait échouer toute la ligne.
  - `interface RadarCheckDeps { fetchReleases(e: RadarEntry): Promise<RadarRelease[]>; fetchEpisodes(e: RadarEntry): Promise<TmdbEpisode[]>; library: LibraryEntry[]; now: number; today: string }`
  - `checkEntries(entries: RadarEntry[], deps: RadarCheckDeps): Promise<{ updates: Map<string, EntryUpdate>; failed: string[]; newAlerts: { entry: RadarEntry; alert: RadarAlert }[] }>` avec `CHECK_CONCURRENCY = 2`
  - `shouldCheck(entry: RadarEntry): boolean` (`!isComplete(entry)`)
